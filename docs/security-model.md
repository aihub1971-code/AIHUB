# AI HUB 1.5.1 security model

This documents source version 1.5.1. Version 1.5.0 was deployed at 2026-10-20 08:56:59 UTC from commit `f00d43deb644ed4ce0a17ef8866183df85bb6d9f`; its live NewsData test retrieved 20 distinct articles from 19 publishers with saved Arabic translations. The first-20 cap and public-interface checks for 1.5.1 are recorded separately in [validation](VALIDATION_AR.md).

## Scope and identity

AI HUB has a public user interface at `/` and a single-owner administration interface at `/admin`. Public users can use the 13 assistants and chat without owner credentials; public responses omit costs and administrative records. HTTP Basic authentication still protects administrative `/v1/*` routes, including the owner's history, report downloads, usage, configuration flags and schedules. The explicitly public `/v1/public/*` prefix uses anonymous session ownership instead. `APP_USERNAME` and `APP_PASSWORD` are compared in constant time. Publishing the user interface does not expose these credentials or remove owner-route authentication.

Use HTTPS for remote access. `/`, the `/admin` sign-in shell, static assets, `/health` and `/v1/public/*` are intentionally public; protected administration data still requires owner authentication. `/health` checks liveness without calling OpenAI; it does not prove that the API key, model or web-search access works. Interactive API documentation is disabled by default. `ENABLE_API_DOCS=true` makes `/docs` and the schema public and is intended for local development.

The administration browser keeps authentication only in memory. Its sole application preference in `localStorage` is `aihub.language`. The authenticated request callback accepts same-origin `/v1/` paths and does not expose the authorization header to the chat module. Logout clears private page state, aborts active requests and prevents late responses from repopulating the page. The administration design does not provide multiple owner accounts, roles, MFA or individual owner-session revocation.

## Public visitor sessions

The public bootstrap creates a 30-day, host-only `HttpOnly`, `SameSite=Strict` cookie; it is `Secure` on HTTPS, including Render-forwarded HTTPS. No owner login or Authorization header is required by `/v1/public/*`. Reports and runs are mapped to the visitor session in SQLite. Public conversations use a distinct owner identity per session, separate from the administrator. Explicit and inherited report attachments must belong to the same session. Knowing an administrative or another session's report/conversation ID does not grant access.

Cross-origin public mutations are rejected. Public serializers omit accounting amounts, provider credits, usage, model/configuration details, provider cursors and private report identifiers. Public execution still uses the shared server-side quota and reservation gates; hiding costs does not disable those limits. The visitor cookie is anonymous session access, not a registered user account or a claim of cross-device identity. Provider keys remain server-side.

## Provider permissions and evidence boundaries

`agents.json` and `config/permissions.json` permit `newsdata` for `iran-news`; that assistant has no `web_search` capability. Other research agents retain OpenAI-hosted web search. Missing permissions deny access. Tasks, skills and retrieved content cannot grant additional tools or external actions.

The Iran adapter makes one HTTPS GET to the fixed NewsData latest endpoint, using a server-side `X-ACCESS-KEY` header. Its query is fixed to `iran war` (AND), original language English, deduplication enabled, UTC timestamps and descending publication order. Task prose cannot alter the endpoint, query or filters. It uses the latest48-hour window, not paid archive or timeframe parameters. The previous six-publisher restriction does not apply to this provider flow. Returned public article links still require safe URL and hostname validation; the adapter does not fetch arbitrary publisher URLs on the server.

The configured page size defaults to10 and must be1–50, subject to the provider plan. Each execution fetches exactly one page with bounded response size. Each search considers only the first 20 provider results before validation, so fewer accepted articles may be displayed. The effective request size is bounded by the configured size, the remaining allowance out of 20, and the provider plan; Next ends at that cap or provider exhaustion. The first page freezes a48-hour window and its size for continuation. Provider cursors are stored privately in SQLite; the client supplies only `continue_from_report_id` for an existing saved report. Raw cursors are omitted from public reports and downloads. A saved child is reused; Previous is a read of persisted data. There is no automatic pagination loop or failed-request retry.

Articles preserve their provider identity, original headline/description, publisher, direct article URL and publication metadata. The server checks required display fields, URL safety, publication time and duplicates. `pubDate` with `pubDateTZ` establishes supplied publication metadata; `fetched_at` is collection time and cannot replace it. `source_url` is the publisher homepage, not an article fallback. Plan-notice strings are not article evidence. Provenance is `newsdata_structured_metadata` with `publisher_text_verified=false`; no independent full-text verification or paywall access is claimed. The free plan's12-hour delay can affect freshness. See the [official NewsData specification](https://newsdata.io/openapi.json) and [plan limits](https://newsdata.io/blog/pricing-plan-in-newsdata-io/).

Arabic translation is prepared for each retrieved page regardless of interface language, in OpenAI batches of at most five articles. The translation receives only bounded original headline/description fields and stable article IDs, treated as untrusted data. It has `tools=[]` and cannot browse, change links or supply new article metadata. The server validates identities and translated field shape; an empty original description stays empty. Originals survive missing configuration, partial translation and provider failure. Both display languages are saved, so toggling the interface makes no new model request. Translation is not independent factual verification.

Other OpenAI research assistants retain their approved-domain policy (`ft.com`, `theatlantic.com`, `politico.com`, `politico.eu`, `wsj.com`, `telegraph.co.uk`, `aljazeera.com`, `aljazeera.net`). Native sources authorize their links, and model notes remain attributed evidence rather than independently fetched publisher bodies. Other news reports retain bounded discovery, at most one optional evidence/breadth follow-up, and synthesis when evidence exists, with one native action per research request and20 combined main/background items. Other search tasks have one research request plus an answer; chat and non-search tasks have no search tools. The OpenAI publisher restrictions do not apply to NewsData Iran pages; that flow has its own first-20 provider-result cap described above.

The browser inserts structured article fields as text and uses a limited Markdown renderer without raw HTML. Article links open with `noopener noreferrer`; saved NewsData content is rendered using its provider-aware URL checks. Old report formats remain readable. The application does not send WhatsApp messages, emails or invitations, or publish generated reports to third parties.

## Chat context and language

Conversations, messages and turn states are stored in owner-scoped SQLite records; each public session has its own owner identity, separate from the administration owner. The client submits a message, language and optional selected report; it cannot supply system messages or forged assistant history. The server retrieves recent completed user/assistant pairs itself. A conversation permits one pending turn, and a history-version check prevents sending a request prepared against changed history.

Chat context is bounded to 20 completed turns within 100,000 serialized bytes, an explicitly selected completed report within 30,000 bytes, and a total payload within 200,000 bytes. A message may contain up to 8,000 characters; a conversation title is limited to 120. Older context may be omitted without deleting stored history, and truncation is reported. The selected report is labeled untrusted archived data and is not the full database. The server-whitelisted platform context identifies the **العربية** and **English** buttons in the page header and explains the fixed Iran-war latest-news flow and the separate task controls for other assistants. These factual interface instructions add no tool or action permissions. Chat has no callable tools, live web search, filesystem access or permission to change settings, schedules or reports. These boundaries limit actions; they do not guarantee the factual correctness of generated prose.

Arabic and English are stored with new reports and schedules. Changing interface language updates page direction and controls without making an OpenAI call. NewsData pages display their saved Arabic or English fields; other archived reports keep their original language. A report can be explained or translated in chat while its saved original remains unchanged. The additive migration creates chat tables and adds `schedules.language` with `ar` for existing schedules; existing Arabic report idempotency hashes remain stable. See [Chat and language guide](CHAT_AND_LANGUAGES.md).

## Secrets and stored data

The private configuration values are `APP_USERNAME`, `APP_PASSWORD`, `OPENAI_API_KEY` and `NEWSDATA_API_KEY`. NewsData is required for Iran retrieval; OpenAI provides its optional Arabic translation and remains required for other assistants and chat. Keep them in a private environment file or the Render service environment. The browser never receives the provider key. Do not place credentials in code, repository URLs, screenshots or support messages. `.env.example` contains empty credential fields; CI uses synthetic credentials.

For Iran retrieval, NewsData receives only the fixed query/filter request and any server-held page cursor; it does not receive the user task or chat history. OpenAI receives the bounded article fields for Arabic translation. Other assistant tasks, selected skills and research material are sent to OpenAI for report generation. Chat sends the current message, bounded completed history, selected report context and whitelisted platform facts. Requests set `store:false`, while AI HUB keeps its own history in SQLite. This flag is **not a promise of zero provider retention**: separate abuse-monitoring and feature-specific retention rules may apply. Consult [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) and the account's applicable settings.

SQLite contains sensitive tasks, reports, schedules, conversations and accounting records at `AI_HUB_DATABASE_PATH`. On Render, the database and WAL sidecars must be under `/var/data/ai-hub` on the persistent disk. The source packager excludes runtime data; it cannot detect every secret pasted into ordinary source files. Use the SQLite-native backup script, keep backups private and copy them off the service disk. Backups contain the same sensitive content as the live database.

## Usage controls and billing

Before provider calls, an atomic SQLite transaction reserves report capacity, any NewsData credit and the conservative estimate for all planned OpenAI stages. NewsData latest pages reserve exactly one credit and optional Arabic translation cost; a page without available translation may reserve zero USD plus one credit. The local `NEWSDATA_DAILY_CREDIT_LIMIT` defaults to200 and is a non-negative integer. Credits remain separate from USD, and the ledger never invents a dollar-per-credit subscription price. Every newly fetched Next page consumes another report attempt and credit; saved Previous/child reads do not. The authenticated `/v1/usage` exposes the separate NewsData credit totals to the owner; public responses omit accounting and usage fields. Default shared estimated budgets are **$5 per day and $100 per month**. Public and administrative reports, scheduled reports and chat turns all consume these USD budgets. The separate maximum of **50 accepted report attempts per day** applies only to manual and scheduled reports. Chat has a separate ledger and conversation history; it does not consume that report-attempt quota or appear as a report in the report archive. Usage exposes both the combined cost and separate report/chat totals.

Chat messages require an `Idempotency-Key`. A matching replay returns or identifies the existing turn without another provider call; changing its message, language or report selection rejects the key. Report replays likewise preserve task/language identity. Pending, interrupted and ambiguous failed attempts retain their reservation. Missing usage, unexpected billing metadata and failed research prevent downward reconciliation. Restarts record stale pending work as interrupted instead of resending it. An explicit new attempt with a new key is a new potentially billable operation.

Failed or interrupted provider work retains its reservations when billing is uncertain. Accounting is deliberately conservative and may exceed the eventual invoice. Prices are tied to the configured model, with native search fees configured separately. These controls cover only this application, not other uses of the same key, hosting, taxes or account-specific billing terms. OpenAI billing records determine invoiced API charges. Persistent limits require persistent SQLite storage.

## Scheduler and deployment boundary

Use one Uvicorn process with `--workers 1`, one Render instance and one attached disk. `SCHEDULER_ENABLED=false` is the default; both the global scheduler and each schedule must be enabled for automatic execution. Atomic occurrence claims and stable idempotency keys prevent a restart from resending an already claimed occurrence. Old missed occurrences are skipped instead of triggering an uncontrolled catch-up burst.

This architecture does not provide horizontal scaling or guaranteed uninterrupted scheduled delivery. Disk-backed Render services have a deployment interruption; their disk is not shared with other services or mounted during builds or pre-deploy commands. See the [official Render disk documentation](https://render.com/docs/disks).
