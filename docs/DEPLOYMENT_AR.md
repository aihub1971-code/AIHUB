## البنية

خدمة Python واحدة، وعملية Uvicorn واحدة، و**عاملا مهام داخل التطبيق**. المهام والتقارير والمحادثات في SQLite على القرص الدائم، وPDF في `reports/` بجانبها. لا تحتاج هذه البنية إلى Redis أو عامل Render منفصل.

| الإعداد | القيمة |
|---|---|
| المستودع | [aihub1971-code/AIHUB](https://github.com/aihub1971-code/AIHUB) |
| الخدمة الحالية | `srv-dbb0v3s9v7es73a9o3j0`، اسمها `ai-hub` |
| المنطقة / Runtime | Frankfurt / Python 3.12 |
| Build | `python -m pip install -r requirements.txt` |
| Start | `python -m uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1` |
| Health | `/health` |
| القرص | القرص القائم 1 GB عند `/var/data/ai-hub` |

راجع [توثيق أقراص Render](https://render.com/docs/disks) قبل تغيير النسخ أو القرص؛ الملفات خارجه ليست تخزينًا دائمًا. راجع السعر النهائي والذاكرة في لوحة Render عند تعديل الحوسبة؛ لا تفترض أن سعر استضافة قديم لا يزال ساريًا.

## إعداد البيئة في 2.0.4

ضع الأسرار في Environment الخاصة بالخدمة، لا في GitHub أو المتصفح:

| المتغير | القيمة أو الدور |
|---|---|
| `NEWSDATA_API_KEY` | المفتاح القائم للمجالات الإخبارية السبعة؛ لا تُظهر قيمته |
| `NEWSDATA_PLAN` / `NEWSDATA_PAGE_SIZE` | تهيئة الخطة لا تثبت استحقاق الحساب؛ صفحة حتى 10 عند `unknown`/`free` وحتى 50 عند `paid` |
| `NEWSDATA_DAILY_CREDIT_LIMIT` | `200` قائم، مشترك مع الاستخدام السابق |
| `OPENAI_API_KEY` | تحليل الأخبار وترجمتها والمحادثة؛ البحث الأصلي للتاريخ والإبداع |
| `OPENAI_MODEL_NAME` / `OPENAI_REASONING_EFFORT` | `gpt-6.1-sol` / `low` |
| `APP_USERNAME` / `APP_PASSWORD` | حساب المالك |
| `MAX_REPORTS_PER_DAY` | `100` حسب طلب المالك |
| `DAILY_BUDGET_USD` / `MONTHLY_BUDGET_USD` | `900` / `28000` |
| `REPORT_WORKER_ENABLED` / `REPORT_JOB_WORKERS` | `true` / `2` |
| `SCHEDULER_ENABLED` | `false` |
| `AI_HUB_DATABASE_PATH` | `/var/data/ai-hub/ai-hub.sqlite3` |

السقوف المالية تستوعب الحجز المحافظ للبحث؛ ليست توقعًا للإنفاق ولا اشتراكًا. تبقى ميزانية حساب OpenAI مستقلة. [أسعار النموذج](https://developers.openai.com/api/docs/models/gpt-6.1-sol) و[حجز التطبيق](OPERATIONS_AR.md).

تحتاج الأخبار الحالية إلى `NEWSDATA_API_KEY` القائم. احتفظ بقيمه الخاصة، ولا تغيّر الخطة أو الرصيد لتجاوز رفض المصدر. الجلب محدود بـ 100 مقال مقبول من 12 ساعة و 20 صفحة/90 ثانية، مع فاصل مخزن 15 دقيقة وتهدئة مشتركة عند الخطأ؛ لا يستدعي تحديث المخزن نموذجًا. التحليل والترجمة طلبات تقرير محدودة بلا أدوات ومحجوزة الميزانية؛ لا ترفع إعدادات المخرجات لتجاوز الحجز. الأخبار ذات `provider_metadata_only` لا تثبت فحص صفحة الناشر.

`render.yaml` يصف الخدمة مباشرة؛ تغييره في 2.0.4 تعليقات تفسيرية فقط، دون تعديل البناء أو الميزانيات أو عدد النسخ أو القرص. راجع [مرجع Blueprints](https://render.com/docs/blueprint-spec). تحقق من وجود الأسرار المطلوبة في Environment للخدمة القائمة دون كشفها.

## البناء والخطوط

يشغّل Render `app/` من المستودع؛ لا يفك ZIP أثناء البناء. ثبّت `requirements.txt` كما هو. PDF يستخدم `fpdf2` و`uharfbuzz`، مع Noto Sans وNoto Sans Arabic العادي والعريض في `app/assets/fonts/`. ترخيص SIL OFL 1.1 و`OFL.txt` و`SOURCES.json` جزء من التسليم. [تشكيل النص في fpdf2](https://py-pdf.github.io/fpdf2/TextShaping.html).

## تسلسل التحديث

1. احتفظ بنسخة احتياطية من SQLite وPDF الخاصة؛ لا ترفعها إلى المستودع العام.
2. شغّل الاختبارات الاصطناعية وفحوص الواجهة وPDF، ثم تحقق من CI.
3. احتفظ بالقيم القائمة:100 محاولة تقرير، و 900/ 28000 لسقفي الدولار، و 200 رصيد NewsData. احتفظ بالمفاتيح والقرص والمسار والعمال والجدولة المعطلة؛ لا تصفر سجل المحاولات أو الرصيد ولا تغيّر استحقاق المصدر.
4. انشر commit الذي اجتاز CI وسجّل بصمته في `docs/VALIDATION_AR.md`.
5. طابق `/health` والأصول المخدومة مع 2.0.4، وتحقق من تسعة مساعدين نشطين وسبعة مجالات أخبار ومنع التنفيذ الجديد للأربعة المتوقفين. راجع حالات المخزن والأخطاء ووقت آخر نجاح، مع بقاء الحصص والميزانيات والسجل. لا يعني نجاح الصحة أو الأصول نجاح تغطية الأخبار.
6. أعد قراءة نسخة قديمة وPDF والمحادثة بعد إعادة التشغيل، مع مقارنة البصمات والملكية؛ لا ينشئ فحص الحفظ بحثًا جديدًا.

الصحة وحدها لا تختبر وصول النموذج أو تأخر NewsData. عند فتح لوحة الأخبار قد يبدأ GET تحديثًا مقيدًا يستهلك رصيد المصدر، رغم أنه لا يستدعي نموذجًا؛ لا يُحسب ذلك فحص قراءة محفوظة بلا أثر مزود. نفّذ الفحص الحي ضمن العمل المصرح به وسجّل العدد والتوقيت والقيود الفعلية، دون إدخال قديم أو افتراض نجاح جديد.

في التشخيص السابق لهذا الإصدار، عند 2026-10-20 18:11:09 UTC، كانت أحدث مادة في صفحة إيران 06:10:59 UTC؛ المقالات العشرة خارج 12 ساعة وعددها المؤهل صفر. رفض حجم 50 وحدد 1–10. لا يثبت ذلك خطة مجانية، ولا يثبت أن النشر وحده سيمنح وصولًا آنيًا. تبقى الحالة الجديدة معلّقة حتى يوثّق الفحص الفعلي.

أداة المساحة هي `scripts/workspace_smoke_test.py`: وضع `--live` ينفذ مهام فعلية، و`--verify-saved` يعيد قراءة النتائج المحفوظة. احتفظ ببيانات جلسة الاختبار ومخرجاتها خارج GitHub. فحص 2.0.0 شمل سبعة تقارير عربية مكتملة وPDF، وإخفاق Moodboard؛ لا يُحوّل ذلك إلى ادعاء نجاح المساعدين الثمانية في التصحيح.

## الاستعادة

العمل المدفوع الذي انقطع بعد الحجز لا يُعاد تلقائيًا؛ تبقى حالته وقيمة الحجز. يمكن استئناف عمل لم يبدأ استدعاءه، وإعادة إخراج PDF من تقرير محفوظ دون بحث جديد. آخر تقرير ناجح يظل متاحًا.

أبقِ Uvicorn بعملية واحدة مع القرص المحلي الحالي. عاملا التقارير داخل العملية يستخدمان ملكية مهام ومهلات تجديد في التخزين؛ لا تضاعفهما بتشغيل خدمات على ملفات SQLite منفصلة.
