# نشر AI HUB 2.1

تصف هذه التعليمات تحديث المصدر على الخدمة القائمة. **لا تتضمن إعلان نشر أو نجاح فحص حي.** يضيف مسؤول الإصدار commit ونتائج CI ومعرف النشر وتوقيته ونتائج التحقق الفعلية إلى [سجل التحقق](VALIDATION_AR.md). تبقى ملاحظات الإصدارات 2.0 السابقة أدلة تاريخية تخص تلك الإصدارات.

راجع [دليل الترقية](UPGRADE_2_1.md) قبل النشر: الواجهة الحالية سبعة وكلاء، وفتح الوكيل لا يبدأ عملًا، والتحديث يدوي، وسقف NewsData هو 50 نتيجة خام، ويمكن للعمل الصريح استخدام بحث ويب محدود ومدفوع ضمن السقوف القائمة.

## الخدمة والتخزين

استخدم الخدمة والقرص الحاليين؛ لا تنشئ قاعدة فارغة لتطبيق الترقية. التطبيق خدمة Python واحدة بعملية Uvicorn واحدة وعاملي تقارير داخل العملية. لا تحتاج البنية الحالية إلى Redis أو عامل Render منفصل.

| الإعداد | إعداد المشروع |
|---|---|
| المستودع | [aihub1971-code/AIHUB](https://github.com/aihub1971-code/AIHUB) |
| خدمة Render القائمة | `ai-hub` / `srv-dbb0v3s9v7es73a9o3j0` |
| Runtime | Python 3.12 |
| Build | `python -m pip install -r requirements.txt` |
| Start | `python -m uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1` |
| فحص الصحة | `/health` |
| القرص | القرص القائم عند `/var/data/ai-hub` |
| قاعدة البيانات | `/var/data/ai-hub/ai-hub.sqlite3` |
| PDF | `reports/` بجانب قاعدة البيانات |

التحديثات البنيوية في SQLite إضافية وتحافظ على التقارير والمحادثات والأرصدة. احفظ نسخة احتياطية خاصة وفق إجراء الخدمة المعتاد، مع ملفات PDF؛ لا ترفع بيانات التشغيل أو النسخ الاحتياطية إلى GitHub. احتفظ بالخطوط المرفقة وترخيص SIL OFL وملفات المصدر والبصمات الخاصة بها.

## الإعدادات الخاصة

| المتغير | الدور أو إعداد المشروع القائم |
|---|---|
| `NEWSDATA_API_KEY` | وصول الأخبار؛ تبقى القيمة سرية |
| `NEWSDATA_PLAN` / `NEWSDATA_PAGE_SIZE` | تهيئة الوصول وحجم الصفحة، وليسا إثباتًا لاستحقاق الحساب |
| `NEWSDATA_DAILY_CREDIT_LIMIT` | `500` في الإعداد الحالي؛ سقف محلي منفصل عن رصيد حساب NewsData |
| `OPENAI_API_KEY` | المحادثة والتحليل والترجمة وبحث الويب المحدود لجميع الوكلاء |
| `OPENAI_MODEL_NAME` / `OPENAI_REASONING_EFFORT` | `gpt-6.1-sol` / `low` |
| `APP_USERNAME` / `APP_PASSWORD` | مصادقة المالك |
| `MAX_REPORTS_PER_DAY` | `500` في الإعداد الحالي؛ حصة بحث مشتركة للتقارير وبحث الويب في المحادثة، مع بقاء الاسم البرمجي القديم |
| `DAILY_BUDGET_USD` / `MONTHLY_BUDGET_USD` | `900` / `28000` في إعداد المشروع |
| `REPORT_WORKER_ENABLED` / `REPORT_JOB_WORKERS` | `true` / `2` |
| `SCHEDULER_ENABLED` | `false` للتشغيل اليدوي |
| `ENABLE_API_DOCS` | `false` في إعداد النشر |

احتفظ بالأسرار والميزانيات القائمة دون عرض قيمها الخاصة أو إعادة ضبط الاستخدام. قيم السقوف ليست توقعًا للفاتورة ولا بديلًا عن رصيد المزود. لا تحاول تجاوز رفض NewsData بكتابة `paid` في الإعداد؛ استحقاق الحساب يحدده المزود. وأصبح وصف التحديث اليدوي بأنه بلا استخدام نموذج غير صحيح، لأن المسار الإضافي المحدود قد يستخدم OpenAI.

تشغّل الخدمة `app/` من المستودع مباشرة. لا تفك حزمة التسليم ZIP داخل خطوة البناء، ولا تحذف مواد المصدر المؤرشفة لتغيير عدد الوكلاء المعروض.

## التحقق قبل النشر

شغّل اختبارات Python وواجهات JavaScript وفحوص PDF في بيئة اصطناعية، ثم تحقق من CI للـcommit المراد نشره. تحقق خصوصًا من:

- وجود الوكلاء السبعة وصلاحيتي NewsData وبحث الويب لكل منهم، ورفض التنفيذ الجديد للوكلاء المتوقفين.
- استعادة محادثة مستقلة لكل وكيل، وفصل الزوار عن المالك، وعدم مشاركة ملاحظات غير معتمدة.
- عدم بدء خبر أو تقرير أو نموذج عند فتح البطاقة أو تبديل الوكيل أو اللغة أو قراءة API المحفوظة.
- إيقاف NewsData عند 50 نتيجة خام، وعرض حدود الأدلة وأخطاء التطبيق والمزود بصورة مختلفة.
- البث الفعلي واستعادة المحاولات بالمفتاح نفسه، والتقارير الخلفية المؤرخة وPDF بالعربية والإنجليزية.
- بقاء `/admin/agents` و`/v1/workspace/*` محميين، مع عمل واجهة الزائر دون بيانات المالك.

هذه نقاط تحقق مطلوبة، وليست ادعاءً بأنها نُفذت حيًا. يسجل مسؤول الإصدار النتائج الفعلية.

## ما بعد النشر

طابق commit المنشور وإصدار الصحة والأصول الثابتة مع المصدر الموافق عليه. افتح الصفحة الرئيسية ومساحة وكيل وتاريخًا محفوظًا باللغتين؛ هذه قراءات لا تتطلب طلبًا إلى مزود. تحقق من عرض محادثة الوكيل ومن أن الانتقال لا يرسل `POST` بحث أو تحديث. اختبر مسار المالك بهوية المالك، ومسار الزائر بهوية زائر منفصلة.

أعد قراءة تقرير محفوظ وPDF بعد إعادة التشغيل وقارن البصمات والملكية عند توافر سجل مرجعي. أبقِ `/admin` متاحًا للصيانة، وتحقق من رابطه إلى `/admin/agents`.

فحص المزود الحي عمل مستقل يبدأ بتحديث أو تقرير أو سؤال صريح، ويمكن أن يستهلك رصيد NewsData واستخدام OpenAI. سجّل عدد النتائج الخام والمقبولة، وأحدث وقت نشر، ومراحل الجلب، وأي خطأ أو قيد فعلي. لا تستخدم مقالًا قديمًا لإظهار نجاح نافذة 12 ساعة، ولا تستنتج أن نجاح `/health` يثبت نجاح وصول النموذج أو الأخبار.

عند استعمال أدوات smoke، اقرأ خياراتها أولًا؛ `--live` ينفذ عملًا حقيقيًا، بينما قراءة النتائج المحفوظة لا تعيد البحث. نتائج الأدوات السابقة تخص العقود والإصدارات التي اختبرتها، ولا تكفي وحدها لاعتماد 2.1.

## التعثر والاستعادة

لا تعِد عملًا مدفوعًا ملتبسًا تلقائيًا. راجع هوية المهمة وحالتها وسببها الآمن، واحتفظ بآخر تقرير ناجح. فشل PDF بعد الحفظ يعالج بإعادة إخراج محلية. تهدئة المزود تبقى ملزمة؛ الخطأ المحلي يمكن إعادة فحصه صراحة بعد معالجة سببه، مع استمرار حماية السجل.

لا تغير عدد نسخ الخدمة أو عمليات Uvicorn أو مسار القرص لمجرد معالجة تعثر تقرير. تفاصيل الحجز والمهل والملكية في [التشغيل](OPERATIONS_AR.md) و[نموذج الأمان](security-model.md).
