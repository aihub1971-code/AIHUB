## 3. أوامر التحقق

بعد إعداد البيئة كما في `README.md`:

```bash
python -m pytest
python scripts/validate_blueprint.py
python scripts/package_handoff.py --output dist/AI_HUB_Project.zip
```

يمكن تمرير نسخة محفوظة من مخطط Render الرسمي إلى `--schema` للتحقق دون إنترنت. التحقق البنيوي لا ينشئ موارد ولا يثبت قبول إعدادات الحساب أو صحة المفتاح. حزمة التسليم تضم المصدر وملفّي المتابعة وتستبعد بيانات التشغيل والأسرار.

## 4. ما بقي للتحقق بعد التحديث

1. اكتمال اختبارات التحديث وCI، ثم التحقق من أن Render يشغّل commit الخاص بالإصدار 1.2.1 وظهور النسخة نفسها عبر `/health`.
2. إبقاء بيانات دخول المالك و`OPENAI_API_KEY` في البيئة الخاصة، مع بقاء المجدول متوقفًا.
3. قراءة التقرير الناجح المحفوظ وإعادة فحص مرشحاته مع محلل 1.2.1، ومراجعة الروابط والتواريخ والعدد دون طلب OpenAI جديد.
4. مقارنة تقدير السجل بالاستخدام الظاهر لدى OpenAI، مع تمييز الاحتياطي عن التكلفة المقدّرة بعد اكتمال الطلب.
5. التحقق من بقاء التقرير والحصة بعد إعادة تشغيل الخدمة على القرص الدائم.
6. تفعيل المواعيد اليومية بعد نجاح ما سبق واعتماد أوقاتها.

المصادر المسموح الاستشهاد بها تؤخذ من بيانات أداة البحث. الملاحظات المستخلصة منها والتواريخ قد تعتمد على قراءة النموذج؛ لا يثبت ذلك صحة كل استنتاج أو استقلال كل مصدر. حد 50 سقف للمحاولات المقبولة، ولا يضمن اكتمال 50 تقريرًا أو تغطية جميع أخبار الناشرين يوميًا.
