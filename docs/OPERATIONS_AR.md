# AI HUB — التشغيل والتقارير والميزانية

## 1. الإعداد قبل أول تقرير حي

المفاتيح يضعها المالك داخل `.env` محلي خاص أو في Environment الخاصة بخدمة Render. التطبيق يرسل مهامك وسياق المهارات والمصادر إلى مزود النموذج، ويرسل استعلامات البحث إلى Tavily. لا تحتوي حزمة المصدر على مفاتيح حقيقية.

| المتغير | القيمة الافتراضية / دوره |
|---|---|
| `APP_USERNAME` | اسم مستخدم خاص بالمالك؛ اختر اسمًا بحروف لاتينية |
| `APP_PASSWORD` | كلمة مرور عشوائية طويلة للمالك |
| `OPENAI_API_KEY` | مفتاح OpenAI API الخاص بالخادم |
| `OPENAI_MODEL_NAME` | `gpt-6.1-sol` |
| `OPENAI_REASONING_EFFORT` | `low` |
| `MAX_OUTPUT_TOKENS` | `4096`؛ حد إخراج لكل طلب، ويشمل ما يحتسبه المزود ضمن الإخراج |
| `TAVILY_API_KEY` | مفتاح البحث؛ مطلوب لتقارير الأخبار |
| `AI_HUB_DATABASE_PATH` | قاعدة SQLite المحلية؛ في Render يجب أن تقع تحت القرص الدائم |
| `MAX_REPORTS_PER_DAY` | `50`، ولا يقبل النظام قيمة أعلى من 50 |
| `DAILY_BUDGET_USD` | `5` |
| `MONTHLY_BUDGET_USD` | `100` |
| `SCHEDULER_ENABLED` | `false` حتى تفعيل التشغيل اليومي |
| `ENABLE_API_DOCS` | `false`؛ يمكن تفعيله محليًا فقط لتصفح `/docs` |

عند وجود مفتاح OpenAI يستخدمه التطبيق أولًا. احتُفظ بمسار Groq اختياري للتوافق؛ لا يحدث تبديل تلقائي إلى مزود آخر عند فشل الطلب. تهيئته تحتاج إلى `GROQ_API_KEY` و`MODEL_NAME` وأسعار صريحة تطابق النموذج المختار.

ظهور «الإعدادات موجودة» أو نجاح `/health` يعني أن الخدمة تستجيب أو أن الحقول المطلوبة موجودة. لا يثبت ذلك صلاحية المفتاح أو الرصيد أو الوصول للنموذج أو نجاح بحث حي. واجهة `/v1/system` لا تجري اختبارًا مدفوعًا، وتعيد `live_connection_verified: false` لأن الفحص الحالي لا يتحقق من الحساب مباشرة؛ ارجع إلى نتيجة الطلب الفعلي وسجله.

## 2. الاختبار الحي الأول

1. شغّل الاختبارات المحلية بـ `python -m pytest`. تستخدم الاختبارات بدائل للمزودين ولا تحتاج مفاتيح إنتاج.
2. شغّل التطبيق بعملية واحدة واترك المجدول متوقفًا.
3. نفّذ `python scripts/smoke_test.py` لفحص الصحة والمصادقة وقائمة المساعدين الـ13.
4. من الواجهة، اختر مساعدًا إخباريًا وأرسل مهمة واضحة بفترة زمنية محددة، أو شغّل `python scripts/smoke_test.py --live --agent iran-news`.
5. راجع الروابط وتواريخ النشر وعدد الأخبار والتنبيهات وتقدير التكلفة، ثم تأكد من ظهور التقرير في السجل.
6. أعد تشغيل التطبيق وتحقق من بقاء التقرير والاستهلاك. في Render يجب أن يكون مسار القاعدة على القرص الدائم.

خيار `--live` يطلب تقريرًا واحدًا قابلًا للفوترة؛ لا يبدأ 50 تقريرًا. عند انتهاء مهلة الاتصال، افحص التقرير المحفوظ قبل إعادة الطلب. يدعم API رأس `Idempotency-Key` لإعادة نفس الطلب بالمعرّف نفسه دون تنفيذ جديد؛ تغيير نص المهمة مع استعمال المعرف نفسه مرفوض. يطبع سكربت الفحص `Request ID` قبل التنفيذ؛ يمكن تمرير القيمة نفسها لاحقًا إلى `--request-id` عند مراجعة الطلب نفسه. تشغيل السكربت مجددًا دون هذا الخيار يولد معرفًا جديدًا ويُعد طلبًا جديدًا.

## 3. ماذا تعني «6 أخبار»؟

تقارير المساعدين `iran-news` و`geopolitical-morning` و`uae-eu-trade-talks` و`economic-cultural-briefing` تستهدف 6 بنود إخبارية من نتائج بحث حديثة. يستبعد المحرك روابط الفهارس والمصادر غير المقبولة، يزيل تكرارات واضحة، ويحصر الاستشهادات في المصادر التي جرى استرجاعها.

إذا لم تتوافر أدلة كافية، قد يحفظ التقرير أقل من 6 أخبار ويذكر السبب. أما فشل البحث المطلوب أو إعداداته فيمنع إصدار تقرير أخبار مدّعى أنه حديث اعتمادًا على ذاكرة النموذج وحدها.

تاريخ النشر يختلف عن تاريخ الحدث. قد تكون المقالة منشورة خلال الفترة المطلوبة وتشرح حدثًا سابقًا؛ وقد لا يثبت النص تاريخ الحدث أصلًا. لذلك يُفصل عدد البنود المقبولة عن عدد الأحداث المثبت أنها جديدة خلال الفترة، وتُوسم التواريخ غير المؤكدة بوضوح. هذه الضوابط تساعد في المراجعة لكنها لا تستبدل التحقق التحريري من معنى الخبر واستقلال مصادره.

المساعدون الآخرون يحتفظون بوظائفهم الأصلية. لا يتحول ملخّص محضر اجتماع أو ترجمة أدبية تلقائيًا إلى تقرير من 6 أخبار. مساعد WhatsApp يجهز النص فقط؛ لا ترسل هذه النسخة رسائل إلى أشخاص أو مجموعات.

## 4. حدود الاستخدام والتكلفة

### العدد والاحتياطي

الحصة العالمية تجمع التشغيل اليدوي والمجدول وكل المساعدين: **50 محاولة مقبولة في يوم دبي كحد أقصى**. يفحص النظام الحصة والميزانية داخل معاملة SQLite ويحجز احتياطيًا قبل استدعاء المزود. إذا تجاوز الاحتياطي الميزانية المتبقية، يرفض الطلب قبل إرسال البحث أو توليد النص.

المحاولات الفاشلة أو التي انتهت مهلتها بعد قبولها تدخل في الحصة. لا توجد إعادة تلقائية لطلبات المزودين. يحتفظ التنفيذ الجاري أو الفشل الملتبس بكامل التقدير المحجوز حتى لا تتحول الأخطاء وإعادات التشغيل إلى ثغرة في الميزانية. عند وجود استخدام مكتمل قابل للحساب، يسجل التطبيق تقديره بحسب عدد tokens وسعر البحث.

الحدود تُحسب بحسب `Asia/Dubai`. يبدأ يوم جديد عند منتصف الليل في دبي، ويبدأ شهر جديد عند بداية الشهر هناك. الحصة يومية وليست «آخر 24 ساعة» متحركة. حذف ملف قاعدة البيانات أو استبداله يزيل سجل الحصة؛ حافظ على الديمومة والنسخ الاحتياطي.

### أسعار النموذج والبحث

آخر مراجعة للأسعار المستخدمة: **19 أكتوبر 2026**. المتغيرات قابلة للتعديل لتطابق حسابك وخطتك:

| المتغير | القيمة النموذجية |
|---|---:|
| `OPENAI_PRICING_MODEL` | `gpt-6.1-sol` |
| `OPENAI_INPUT_USD_PER_MILLION` | 2 دولار / مليون token إدخال |
| `OPENAI_OUTPUT_USD_PER_MILLION` | 10 دولارات / مليون token إخراج |
| `TAVILY_CREDIT_PRICE_USD` | 0.008 دولار / رصيد |

تذكر [صفحة النموذج الرسمية](https://developers.openai.com/api/docs/models/gpt-6.1-sol) سعر إدخال 2 دولار وإخراج 10 دولارات لكل مليون token، وإدخال مخزّن 0.10 دولار وكتابة cache قدرها 2.50 دولار. يحتسب التطبيق إدخال OpenAI بمعامل احتياطي 1.25 حتى لا يقل تقديره عن كتابة cache؛ ولا يفترض خصمًا مقابل الإدخال المخزّن. يستخدم مستوى الخدمة القياسي في طلباته. لا تفترض هذه القيم صلاحيتها لنموذج آخر أو معالجة إقليمية أو تسعير خاص بحسابك.

توضح [وثائق Tavily](https://docs.tavily.com/documentation/api-credits) أن البحث المتقدم يستهلك رصيدين، وأن سعر الدفع بحسب الاستخدام 0.008 دولار لكل رصيد. يستخدم هذا الإصدار استدعاء بحث واحدًا للتقرير الإخباري، أي تقديرًا قدره 0.016 دولار للبحث المتقدم. أي أرصدة مجانية أو خطة اشتراك خاصة بحسابك تُراجع في لوحة المزود، ولا يُفترض أنها تلغي الاحتياطي.

**مثال حسابي فقط، وليس قياسًا لتقرير نُفذ:** إذا استهلك تقرير 10,000 token إدخال و2,000 token إخراج وبحثًا متقدمًا واحدًا، يكون التقدير المحافظ `0.025 + 0.020 + 0.016 = 0.061` دولار. خمسون تقريرًا بهذه الفرضية تعادل 3.05 دولارات يوميًا، أو 91.50 دولارًا لشهر من 30 يومًا. تختلف النتائج الفعلية حسب طول المصادر والمهمة والإخراج والفشل. الاحتياطي السابق للتنفيذ أكثر تحفظًا وقد يمنع بعض الطلبات حتى لو كان متوسط الفاتورة النهائية أقل.

حدا 5 دولارات يوميًا و100 دولار شهريًا يعملان معًا: وصول حد الشهر يوقف الطلبات الجديدة حتى مع وجود حصة يومية متبقية. سجل التطبيق **تقدير تعرض مالي** وليس فاتورة OpenAI أو Tavily، ولا يشمل رسوم Render أو القرص أو الضرائب أو استخدام المفاتيح خارج AI HUB. اضبط تنبيهات وحماية الإنفاق في حسابات المزودين أيضًا.

عند تغيير `OPENAI_MODEL_NAME`، غيّر `OPENAI_PRICING_MODEL` والأسعار إلى قيم تطابق النموذج نفسه. يرفض التطبيق التقدير إذا كان ربط النموذج بالأسعار غير صحيح. وبالنسبة إلى Groq استخدم `GROQ_PRICING_MODEL` و`GROQ_INPUT_USD_PER_MILLION` و`GROQ_OUTPUT_USD_PER_MILLION`.

## 5. تفعيل الجدولة اليومية

جدول واحد يمكن أن يحتوي وقتًا واحدًا أو عدة أوقات. الأوقات ثابتة بتوقيت دبي وبصيغة ساعة ودقيقة من 24 ساعة، مثل `08:00` و`16:00`.

مثال جسم طلب `POST /v1/schedules`:

```json
{
  "name": "نشرة أخبار إيران",
  "agent_id": "iran-news",
  "task": "أعد تقريرًا عربيًا بأهم 6 أخبار موثقة في آخر 24 ساعة مع الروابط وتواريخ النشر.",
  "times": ["08:00", "16:00"],
  "enabled": false
}
```

للتفعيل، أنشئ الجدول وراجعه أولًا، ثم اجعل `enabled=true` للجدول، واضبط `SCHEDULER_ENABLED=true` في البيئة وأعد تشغيل الخدمة. احرص على تحديث قيمة الجدولة في `render.yaml` أيضًا عند اعتماد التفعيل، لأن مزامنة Blueprint لاحقًا تعيد تطبيق القيمة الموجودة فيه. يمكن إيقاف جدول منفرد بتغييره إلى `enabled=false`، أو إيقاف المجدول كله بإعادة `SCHEDULER_ENABLED=false`.

- لا يبدأ التشغيل بسبب إنشاء جدول متوقف.
- الحد الأعلى لمجموع الأوقات في الجداول المفعلة هو 50 وقتًا يوميًا، وتشاركها المحاولات اليدوية في حصة التنفيذ الفعلية.
- يراجع المجدول المواعيد كل نحو 15 ثانية، ويشغّلها بالتتابع. وزّع الأوقات على اليوم بدل وضع عشرات التقارير في الدقيقة نفسها.
- توجد مهلة سماح 5 دقائق فقط للموعد المتأخر. إذا انقطعت الخدمة مدة أطول أو تراكمت مهام طويلة، يتجاوز المواعيد الأقدم بدل إطلاق دفعة كبيرة لتعويضها.
- الجدول الجديد لا يشغّل أوقاتًا سبقت إنشائه، وتعديلات الجدول أو إعادة تفعيله تسري على الأوقات التالية للتعديل فقط.
- يحجز المجدول الموعد في قاعدة البيانات قبل التنفيذ. إعادة تشغيل الخدمة لا تعيد تلقائيًا موعدًا حُجز سابقًا، ولا توجد إعادة تلقائية لطلب فشل.
- المحاولة المعلقة أكثر من 15 دقيقة تصبح `interrupted` عند إجراء استعادة الحالة، مع الاحتفاظ باحتياطيها.

هذه الجدولة تحتاج إلى خدمة تعمل باستمرار. إطفاء جهاز التشغيل المحلي يوقفها؛ وخطة الاستضافة التي تنام عند الخمول لا تحقق التشغيل المستمر المقصود هنا.

## 6. مرجع API المختصر

كل مسارات `/v1/*` محمية بمصادقة HTTP Basic الخاصة بالمالك. استخدم HTTPS خارج جهازك. لا تُرسل المفاتيح السرية ضمن أجسام طلبات API.

| العملية | المسار | الاستخدام |
|---|---|---|
| `GET` | `/health` | فحص حياة الخدمة، دون اتصال مدفوع بالمزود |
| `GET` | `/v1/agents` | قائمة المساعدين |
| `POST` | `/v1/agents/{agent_id}/run` | تشغيل مهمة بالجسم `{"task":"..."}`؛ يدعم `Idempotency-Key` |
| `GET` | `/v1/system` | وجود إعدادات النموذج والبحث والأسعار وحالة المجدول |
| `GET` | `/v1/usage` | الحصة والاستهلاك اليومي والشهري |
| `GET` | `/v1/reports?limit=10&offset=0` | قائمة النتائج والمحاولات |
| `GET` | `/v1/reports/{report_id}` | سجل تقرير واحد |
| `GET` | `/v1/reports/{report_id}/download?format=md` | تنزيل التقرير كنص Markdown |
| `GET` | `/v1/reports/{report_id}/download?format=json` | تنزيل السجل وبياناته بصيغة JSON |
| `GET` | `/v1/schedules` | المواعيد اليومية |
| `POST` | `/v1/schedules` | إنشاء جدول، متوقف افتراضيًا |
| `PATCH` | `/v1/schedules/{schedule_id}` | تعديل حقول الجدول أو تفعيله/إيقافه |
| `DELETE` | `/v1/schedules/{schedule_id}` | حذف تعريف الجدول |
| `GET` | `/v1/schedule-occurrences?limit=100` | سجل المواعيد المحجوزة والمنفذة والمتجاوزة؛ يدعم `schedule_id` للتصفية |

الحقول `task` محدودة بـ8,000 حرف، وأوقات الجدول لا تتكرر. تنزيل Markdown أو JSON يقرأ النتيجة المحفوظة ولا ينشئ تقريرًا جديدًا. تُظهر استجابة التنفيذ `report_id` وقسم `accounting` الذي يميز بين الاحتياطي والتقدير النهائي.

للتجربة محليًا، اضبط `ENABLE_API_DOCS=true` ثم أعد تشغيل التطبيق وافتح [Swagger UI المحلي](http://127.0.0.1:8000/docs). اضغط Authorize وأدخل بيانات المالك. مخطط API نفسه متاح دون تسجيل دخول عند تفعيل هذا الخيار؛ اتركه `false` في Render.

## 7. النسخ الاحتياطي

تُحفظ التقارير وتعريفات الجداول وسجل الاستهلاك في SQLite. لا تنسخ ملف القاعدة الرئيسي وحده أثناء الكتابة، لأن وضع WAL قد يحتوي بيانات حديثة في ملفات جانبية. استخدم واجهة النسخ الاحتياطي في SQLite عبر السكربت المرفق:

```bash
python scripts/backup_database.py --output ./backups/AI_HUB_Backup_2026-10-19.sqlite3
```

السكربت يقرأ `AI_HUB_DATABASE_PATH`، ينشئ ملفًا جديدًا، ويفحص سلامة النسخة، ويرفض الكتابة فوق ملف قائم. اختر اسمًا جديدًا لكل نسخة. لا تُضمّن ملفات النسخ أو قواعد البيانات في مستودع Git أو حزمة المصدر.

على Render شغّل النسخ من Shell الخاصة **بنفس الخدمة**، واحفظ النسخة تحت `/var/data/ai-hub/backups/` إذا احتجت بقاءها أثناء نقلها. انقلها بعدها إلى وجهة خاصة خارج القرص، مثل جهازك عبر SSH/SCP وفق [وثائق Render](https://render.com/docs/disks). وجود نسخة على القرص نفسه لا يحمي من فقدان القرص.

لا يُستخدم استرجاع لقطة القرص بديلًا لنسخة SQLite المتسقة. لاختبار الاستعادة، استخدم نسخة محلية منفصلة، أبقِ المجدول متوقفًا، واضبط `AI_HUB_DATABASE_PATH` إلى ملف النسخة بعد إيقاف أي عملية قد تكتب إليه. افحص التقارير والحصة قبل نقل الاستعادة إلى الإنتاج. لا تستبدل قاعدة إنتاج وهي مستخدمة من عملية التطبيق.

## 8. تشخيص الأخطاء

| العرض | ما الذي تفحصه؟ |
|---|---|
| `401` | اسم المستخدم وكلمة المرور وطريقة HTTP Basic |
| `503 auth_not_configured` | وجود `APP_USERNAME` و`APP_PASSWORD` في بيئة الخدمة الفعلية |
| النموذج غير مهيأ | المفتاح في Render واسم المتغير والنموذج الصحيح |
| نموذج أو أسعار غير متطابقة | `OPENAI_PRICING_MODEL` وأسعار النموذج المختار |
| البحث غير متاح | مفتاح Tavily ورصيده وصلاحيات البحث للمساعد |
| التقرير أقل من 6 أخبار | كفاية المصادر وتواريخها والفترة المطلوبة؛ راجع تنبيه التقرير |
| `429` من التطبيق | حد المحاولات أو الميزانية اليومية أو الشهرية |
| `409` لمعرّف الطلب | طلب جارٍ أو فشل سابق أو اختلاف المهمة مع نفس `Idempotency-Key` |
| البيانات تختفي بعد النشر | القرص مضاف بالفعل ومسار SQLite يقع تحته |
| المجدول لا يعمل | التفعيل العام، تفعيل الجدول، توقيت دبي، بقاء العملية حية، والميزانية |
| خطأ استيراد الوحدة | Root Directory وأمر التشغيل ووجود `app/` في المستودع |

احتفظ برسالة الخطأ ومعرف التقرير ووقت حدوثه للمراجعة. لا تنسخ مفاتيح API أو كلمة المرور أو رؤوس Authorization إلى سجل دعم أو محادثة.
